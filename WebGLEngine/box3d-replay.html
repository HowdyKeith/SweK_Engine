What this is

Box3D records world mutations and embeds its own state hashes as it goes. This page replays a recording through b3RecPlayer and asks it three questions we could not ask before:

Which frame broke? — box3dSyncCompare.js locates a cross-peer divergence by checkpoint, which means "somewhere in these 150 ticks". The player names the exact frame. The library was always 150× more precise than the tool we built on it.

Does the thread count change the physics? — replaying at a different worker count re-partitions the constraint graph, so the same arithmetic happens in a different order. Every embedded hash must still match. That is not a tautology: a+b+c is not (a+c)+b in floats.

What did it look like? — the player exposes a real world, so the slider below is a scrubber with O(interval) backward seek off a keyframe ring.

Record or load

A recording made on another machine is the honest test: load it here and Box3D decides whether this build reproduces it, hash for hash. Nobody has to trust a number pasted between windows.
