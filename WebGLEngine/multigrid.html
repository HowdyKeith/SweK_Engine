SweK Multigrid Bench

The 2D pressure V-cycle, three ways, on the same problem. Scatter is what the fluid runs today; gather is the GPU-shaped rewrite; device is the WebGPU port, WIRED OPT-IN AS SOLVER mggpu SINCE v3225 — this line said “wired to nothing” for 127 versions after it stopped being true, which is why a sentence about wiring belongs beside a check rather than in prose.
Warm-up runs are executed and thrown away before anything is timed. A single cold pair made the gather path look 1.45× faster than scatter; warmed up it is slower everywhere. That reversal is the reason this page exists.

What the numbers decide, stated before you read them so the reading is not motivated:
• Correctness is already settled. The gather path agrees with scatter to about 1e-7 relative at every size, and fluid/multigridGPU-selfcheck gates that headlessly. This page is not asking whether the port is right.
• The gather column is not a proposal. It exists so the algorithm maps onto a GPU. If it beats scatter here, that is a machine-specific accident of cache behaviour, not a reason to switch the CPU path.
• Only the device column can justify the wiring, and the wiring costs three edits: step() and _project() become async, and fluid-rigid-2d.html awaits. A device column that is merely close to scatter is a REASON NOT TO, because async is a real cost paid every frame.
• The device path is WIRED as of v3225, opt-in and off by default — new Flip2D(nx, ny, { solver: "mggpu", gpuDevice }). It REFUSES without a device rather than falling back to the CPU, because a solver that quietly ran somewhere else would make this whole table meaningless. So the numbers below can now be checked against the real fluid, not just this bench.
• Two substeps per frame. fluid-rigid-2d.html steps twice per rAF, so an awaited device solve is two round-trips inside one frame. Halving a solve that then straddles a frame boundary is not a win.
