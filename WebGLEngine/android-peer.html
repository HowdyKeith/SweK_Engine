what this is - the six items

1Termux path - ai-bridge's 13 required deps are pure JS or WASM, zero native addons: pkg install nodejs + npm install --omit=optional has no gyp step to fail.
2Cheapest real port test - the roundhouse suite: pure Node, CPU-only, self-grading physics gates, zero node_modules needed. A green suite on bionic is a fourth libc for the strict core.
3Second GPU vendor - magmap-android.html runs the unchanged magmap WGSL on the phone's Adreno/Mali against a tolerance set from the emulated f32 floor in v2903, before any second vendor existed.
4Auto-update - refined from "unmodified" to one symlink: the updater scans ~/Downloads, which stock Termux lacks; ln -s ~/storage/downloads ~/Downloads is the whole predicted fix.
5Persistence - the genuinely hard part. Termux:Boot + wake-lock + battery exemption predicted to survive Doze and not survive memory pressure; a real service means a nodejs-mobile wrapper app.
6Won't port - the KPop Listener (PowerShell + /tmp pipes), the Deno GPU Brain (glibc-only; proot fixes libc, loses GPU), the .bat launchers, and the optional ffmpeg/puppeteer heavies.

install - on the phone (Termux)

Get Termux from F-Droid, not the Play Store - the Play Store build is abandoned and its package repositories fail. For termux-wake-lock you need the Termux:API app as well as the termux-api package; the package alone is only the client and the commands silently do nothing. For start-on-boot, add Termux:Boot.

Download SweK_Engine_vNNNN.zip in Chrome first, then paste this whole block into Termux. Pasting multiple lines runs each as it arrives. It picks the highest version number if you have several zips (including Chrome's (1) duplicates), waits for the storage permission dialog instead of racing it, and stops at the first real failure with a plain reason:

pkg update -y && pkg upgrade -y && pkg install -y nodejs unzip termux-api && \
{ [ -d "$HOME/storage/downloads" ] || { echo ">> Tap ALLOW on the storage prompt..."; termux-setup-storage; \
  n=0; while [ ! -d "$HOME/storage/downloads" ] && [ $n -lt 60 ]; do sleep 1; n=$((n+1)); done; }; } && \
{ [ -d "$HOME/storage/downloads" ] || { echo "!! storage still not granted - re-run termux-setup-storage and tap ALLOW"; false; }; } && \
ZIP="$(ls -1 "$HOME/storage/downloads"/SweK_Engine_v*.zip 2>/dev/null | sed 's/.*SweK_Engine_v\([0-9]*\).*/\1 &/' | sort -rn | head -1 | cut -d' ' -f2-)" && \
{ [ -n "$ZIP" ] || { echo "!! no SweK_Engine_vNNNN.zip in Downloads - download it in Chrome first"; false; }; } && \
echo ">> using: $ZIP" && cd "$HOME" && unzip -oq "$ZIP" && \
DIR="$(ls -1d "$HOME"/SweK_Engine_v*/ 2>/dev/null | sed 's/.*SweK_Engine_v\([0-9]*\).*/\1 &/' | sort -rn | head -1 | cut -d' ' -f2-)" && \
cd "${DIR}WebGLEngine" && echo "" && echo ">> READY in: $(pwd)" && \
echo ">> next: bash tools/roundhouse/termux_peer.sh   (15-25 min)"

It deliberately does not launch the suite - that is a 15-25 minute run and should be a decision, not a side effect of pasting an installer.

if unzip says "cannot find or open ... SweK_Engine_v*.zip"

That exact error means the shell glob matched nothing, so the literal * was handed to unzip. The zip is not where the command looked. Diagnose with:

ls ~/storage/           # is 'downloads' even there? if not, permission was never granted
ls ~/storage/downloads/ | grep -i swek
  1. Several zips downloaded. unzip A.zip B.zip does not mean "unzip both" - it means extract the member named B.zip out of A.zip, so a multi-match glob extracts nothing. Name the exact version instead. (The block above does this for you.)
  2. Chrome renamed it to SweK_Engine_v2951 (1).zip - the space and parentheses break an unquoted glob. Quote it: unzip -o "$HOME/storage/downloads/SweK_Engine_v2951 (1).zip".
  3. Storage permission never granted - ~/storage/downloads does not exist at all. Re-run termux-setup-storage and tap ALLOW. Android sometimes revokes it silently after an update.
  4. unzip not installed - the error is unzip: command not found, easy to misread as a path problem. pkg install unzip -y.
two things NOT to add to that block, and why

An external assistant suggested chaining termux-setup-storage && ln -s ~/storage/downloads ~/Downloads && unzip ... && bash termux_peer.sh. Three problems:

  • It races the permission dialog. termux-setup-storage returns immediately; the Android prompt is answered asynchronously. The next command runs before you have tapped ALLOW, so the symlink and the unzip both fail on a directory that does not exist yet. The block above waits for the directory instead.
  • Creating the symlink by hand contaminates claim 4. autoUpdateSymlinksRequired is a prediction the phone is supposed to measure. The probe records what it found; termux_peer.sh performs the fix separately. Making the symlink yourself before the probe runs means the experiment can no longer tell you whether it was required - it just confirms what you did.
  • It auto-launches the 15-25 minute suite as a side effect of an install paste.

move files - copyparty on the phone


This page could run the physics subset and not move a single file. copyparty is a one-file
Python server that runs in Termux and speaks http, WebDAV and FTP, with resumable uploads and downloads.


SweK does not start it and does not install it for you. It is registered in Auto-Install
(v3166) with autoRun deliberately OFF: a file server that starts itself is a decision about what is
exposed and to whom, and that is yours to make, not a registry's.



  
  
not checked yet




The port is 3923 by default - copyparty's own, and it collides with nothing SweK claims
(8787 the engine, 8080 spaceprojectsim). There is no auto-allocator, and that is deliberate: the tree's
freePort() is a KILL - it frees a port by terminating whatever holds it - so a collision here is
REPORTED for you to resolve, never resolved by force. A port that silently drifted would hand you a URL that
changes between sessions.


Read this before serving read-write. copyparty with no accounts gives everyone on the
network read/write access to the folder it serves - its own README says so. The command the checker prints for
iOS is -v .::r, read-only, which is the safer default for a phone. It also carries real CVEs and
publishes advisories, so a copy left running is a thing to keep updated rather than forget.
