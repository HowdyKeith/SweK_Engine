SSAO — two implementations, one decision

A status report called render/SSAOPass.js “proven better AO, never connected”. It has no gate, so proven has no referent; it is filed in the orphan machinery rather than the unwired register, which is a different claim; and orphanScan’s own header already said the part the report left out — 347 lines, 2 exports, zero referrers, while a SECOND SSAO lives inside bloomPass.js. That second one is live: main.js imports BloomPass.

So “better” was never measured against anything. This page exists so it can be. It does not decide.
