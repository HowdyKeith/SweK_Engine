🗿 BZFlag — the network test

Everything in this port is proved against a bzfs built from BZFlag's own source, on the machine that runs the tests. What has never been touched is a real network — the list-server token, and a public server full of people. That part is yours.

Two things I expect to be wrong, so they are not surprises. The token flow has only ever spoken to a local stand-in. And a public server may run a map with group instances, or a plug-in object type — in which case the world walk stops by name and the pilot falls back to observing rather than guessing at a world it cannot see. That refusal is the design working, not a crash.

These routes run brain/bzfsPilot.mjs and nothing else: the script is fixed, there is no shell, and every field above is checked against a pattern before it becomes an argument. A host with a space or a semicolon in it is not a host, and is refused rather than escaped. They answer 403 to anyone who is not the host, an authenticated session, or a LAN peer you have exempted.

1 · Observe a public server

1

No account needed. The pilot joins as an observer: it says hello, downloads the world, and never spawns a tank or sends a position.

node brain/bzfsPilot.mjs --host <server> --port 5154 --callsign geekbot --observe
  • I want server BZFS#### — whether it speaks the protocol version we do.
  • Whether MsgEnter is accepted, or the exact MsgReject <n> text.
  • world downloaded: N bytes → M inflated, md5 verified, and how many obstacles.
  • Any line beginning stopped at "<section>" — that names a record I have not transcribed.

2 · The list-server token

2

Needs a callsign registered at my.bzflag.org. A server running -requireidentify will not take a registered callsign without a token.

BZFS_PASSWORD=<yours> node brain/bzfsPilot.mjs --host <server> --callsign <yours> --observe

The password never touches the command line, because argv is visible to every process on the box through ps. It travels in the child's environment, and it is redacted out of the output below before it is stored.

  • Send me the token: line only. It prints the token's length, never the token.

3 · Play

3

A server whose map you have, or one you host. With no --map the pilot uses the server's own downloaded world — and refuses to drive if it could not read it.

node brain/bzfsPilot.mjs --host <server> --callsign geekbot --seconds 120
  • The ten-second status lines: peers= kills= losses= shots= policy= udp=.
  • Does udp=up appear? Over the internet a NAT may eat the datagram. If it says down that is a finding, not a failure — TCP alone is laggier, not broken.
  • Any oversize=N — a message losing to the 68-byte cap that BZFlag itself never checks.

4 · The browser

4

The viewer reaches the server through this engine's WebSocket-to-TCP proxy, because a browser cannot open a TCP socket. It drives; add &observe to watch.
