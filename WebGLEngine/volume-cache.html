3D texture as a DERIVED CACHE of the RLE chunk

The RLE is canonical. The 3D texture is derived from it, invalidatable, and never a source. This page is the front door: it derives the cache, proves parity voxel by voxel, and -- the part worth watching -- lets you break it in the two ways that matter and shows what each control does and does not see.
A disagreement between the cache and its source is a FINDING, not a glitch. Nothing on this page repairs a divergence. Re-deriving is a separate button you press after you know why.

1. SOURCE (canonical)

An engine-order chunk (world/chunk.js: idx = x + sx*z + sx*sz*y), encoded to RLE. The live engine chunk is 16x64x16; this fixture is wider so the ray march has something to look at, and the gate runs the 16x64x16 shape.

3. PARITY -- position-sensitive, coordinate-reporting, read-only

Built via decodeRLE (linear run walk). Verified via getRLEIndexed (binary search over the prefix index). Two different read paths through the same RLE, so the check has power over a bug in either one.

7. BRICK MAP -- coarse occupancy, and an invariant that fails two different ways

One byte per 8x8x8 brick, derived from the same RLE: 1 if it holds any solid, 0 if it holds none. A DDA over an RLE world pays an O(log runs) binary search per step, and a world is mostly air. The two failure directions are not the same bug: occupied-but-empty costs speed and misses nothing; empty-but-occupied lets a ray pass through a wall, silently. So they are counted separately.
