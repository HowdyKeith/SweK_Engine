How the WASM runs without upstream's service worker

Their build passes Emscripten -pthread, which needs SharedArrayBuffer, which browsers only grant a page real Cross-Origin-Opener-Policy/Cross-Origin-Embedder-Policy response headers for. GitHub Pages can't set those, so upstream ships a service worker that fakes them client-side. This engine's own server can set the real ones directly — see /vpi/app/* in ai-bridge/server.js — so that's what it does. Their coi-serviceworker.min.js still ships and still runs; it's just redundant here rather than load-bearing.
