📊 SweK Excel — the VBA half

This part was started first. Before any of this engine existed there was a VBA transmitter doing Winsock, an OpenGL render engine drawing from a worksheet, and a connector workbook talking to what became SweK. This page is where that work attaches to this install.

The archive is not in this repository, and this page does not put it there. It links to a copy on this machine and reads it. Copying 189 transmitter modules into the tree would fork them — the archive stays what you edit, this tree keeps a snapshot, and the two drift until somebody asks which one a workbook was built from. A pointer cannot drift. It can go stale, and that is a condition this reports rather than hides.

Nothing is ever written inside the archive. It is opened read-only.

1 · Point it at the archive

Extraction lands in ~/.voxelbridge/vba/ — outside this tree on purpose, since every gate here walks every file in the repository. The destination is not a parameter: a zip can carry ../ in its entries.
press Scan, or Link it to store the pointer

2 · The four parts

A folder is recognised by module name, not folder name — yours can be called anything. A part needs two decisive markers, modules only it has. Shared/Net/ in this repository is the trap this is built around: it carries three of the transmitter's Winsock modules because its README says they were extracted from it, so those three corroborate and never decide. A folder with no decisive marker is reported unclassified, not guessed at — and a VBA folder sitting inside a linked part is listed as that part's sub-folder, not as a stranger.

Corrected against a real archive at v4160. SweK_VBA_v3499: transmitter 195, engine 263, connector 64, sync core 4, plus 69 more in VBAEngine/addons/VBAOpenGL_Demos. v4159's guessed markers linked two of the four — the transmitter on 9 of 9 and the connector on 2 of 2 — and missed the other two by exactly one marker each. The threshold was not moved; the markers were widened from the listing. Two guesses were wrong: the render engine declares GL in GLConstants.bas, not the voxel workbook's modGLConstants.bas, so the two workbooks share nothing and the tie v4159 built a branch for does not exist here; and three of VBASyncCore's four names had already been deleted — by the very changelog entry v4159 copied them out of.

3 · Build a workbook from the modules

Excel can build a VBA project from source and openpyxl cannot, so this drives Excel's own VBE through assemble-workbook.vbs. Needs Options › Trust Center › Macro Settings › “Trust access to the VBA project object model”. Per the README's recipe a workbook is its own folder plus Shared/; ThisWorkbook and Sheet* are document modules and are pasted, never imported.

press List VBA folders

4 · Control Excel

An allowlist, not a denylist. Application.Run takes any name and VBA can delete files, reach the network and drive COM — so a denylist would be correct exactly until the archive gained the next dangerous macro. These are the engine's own entry points, refused by name if you ask for anything else. The workbook is opened with events off so Workbook_Open does not fire, and is never saved on the way out.

pick a workbook and a macro

5 · Where the halves meet

  • The connector posts here. Shared/modEngineBridge.bas POSTs each tick to /bridge/game_tick and drains the directives the browser queued. That traffic is what the Excel AI Brains panel on the render page is showing — renamed at v4159, because on a page carrying LLM consoles, GPU brains and a physics-lab roster, “AI Brain” was the one label that never said whose.
  • The transmitter can host instead. ResolveBridgeHost probes Node on :8787, then a transmitter on :8099, and repoints at whichever answers — so the panels stay up with node stopped. That port is not chosen on this page; it is read off the client that has been probing for it all along.
  • The GPU brains are already in the tree. WebGLEngine/vba/ — modGPUBrain, modGPUBrainSteer, modRaycasterDemo. They need the FixPack's clsStringBuilder and JSONParser, which live in the transmitter, which is why those two are decisive markers for it.
⚠️ No Excel has ever run against this. The box this was written on is Linux with no Excel and no copy of the archive. What is measured: the recogniser and the refusals — scanning this whole repository links zero of four parts and calls Shared/Net/ unclassified, which is the correct answer and is asserted by tools/ship/vbaArchive-selfcheck.mjs. What is not: everything past “Excel answered” — assembling a workbook and running a macro. The marker lists are no longer among the unverified: at v4159 they came from this tree's changelog and notes and the manifest reported itself provisional; at v4160 a real archive was scanned, two of the four marker sets were found wrong, and both were widened from its listing. The threshold was never lowered. If a future archive classifies badly, that is still the only correct move.
