## 3. The questions, and what a result would and would not mean
* **Q1. THE PIPELINE (engine, gated here; a CHECK, not a finding).** The request round-trips; every invalid request is refused by its reason; a re-flight is deterministic (flown twice, the same fingerprint); for every seed of the dev set (1-4) and the registered set (101-112) the empty kit reproduces run B's fingerprint and the full kit run K's. If any of these fails the proposal readings are NOT WEIGHED.
* **Q2. CAN A MODEL ASK FOR A RE-FLIGHT? (model; OWED).** Each of the twelve registered pairs is shown to the model as before (the facts) with one new instruction: propose ONE re-flight, in the format above, that would help to see what the kit changed. **VALID** = the reply holds exactly one REQUEST line that parses, validates and names the pair's own seed. Pooled over the twelve: VALID >= 0.9 -> `THE MODEL CAN ASK FOR A RE-FLIGHT`; 0.5 <= VALID < 0.9 -> `THE MODEL SOMETIMES ASKS FOR A VALID RE-FLIGHT`; under 0.5 -> `THE MODEL CANNOT ASK FOR A RE-FLIGHT IN THE FORMAT`. **REPORTED, in no verdict:** the reasons of the refused replies, the share of valid requests that repeat run B or run K (nothing new), the share whose re-flight ends in a different outcome from both, and the kits asked for. **IT WOULD NOT MEAN:** that the model understood why the kit helped or hurt; that the kit it asks for is the informative one; that the model reasons about cause (the engine states what the re-flight did, the model asks and says nothing about why); anything about another model.
* **Q3. SCENARIO 105 (engine; POST HOC, not a verdict).** Fly 105 under all eight subsets and print, per subset: the outcome, the score, the defenders lost, the first divergence from the empty kit and the decoyed and intercepted counts. A reading of WHICH countermeasure's presence changes the fight, not of why. Section 5 holds my forecasts, written before this was flown.
