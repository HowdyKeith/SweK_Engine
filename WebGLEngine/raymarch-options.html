Ray-march options — every control is SEEABLE or MEASURED

An option earns its place only if moving it produces a difference a person can judge or a number the engine reports. A control that is neither is decoration — the “plausible-looking readout with no checkable answer” the lab’s governing rule refuses. Every row below declares its bucket and what it expects, so a run of this page is a test rather than a slideshow.

Both channels at once, never one at a time. The visual and the numeric readout sit side by side, because the value is in whether they agree — the brick skip is right only when the number moves and the picture does not, and a page that showed them in turn would let that disagreement pass unnoticed.

Held while judging. A toggle compared across two camera positions is two pictures, not an A/B, and the difference a person reports is then partly the move. Every option judged by eye names what is pinned while it is judged — the same idea as an engine dyno’s RPM hold, which pins the speed so every other reading becomes comparable.

Where the adjudication lives: a number can refuse while an eye is still deciding, so the cheaper refusal runs first. Every row here is owned by the engine; none is left to taste alone.

What this page does NOT claim

It drives a live context now — that is not the same as being verified. This sandbox has no GPU, so nothing here has been seen to draw. Wiring and working are different claims and the page must not let them read the same.

What a failure looks like: five named causes with five different fixes — no context, program failed to link (with the shader log), no region uploaded, no texture bound, or a throw inside the draw. A blank canvas that names none of them is not a bug report.

And the GPU numbers are still Keith’s. The brick skip’s 94.0% is a CPU figure over 5,000 rays; no GPU number exists. This page can now produce one — it has not.
