🛡️ WASM sandbox — run untrusted code safely …

Type real JavaScript and run it inside QuickJS-in-WASM — with no access to this machine (no require, fetch, process, or filesystem), a memory limit, and an interrupt timeout. The last expression's value is returned.

try these (each is safely contained)
• typeof require / fetch / process → all undefined (no host)
• while(true){} → interrupted by the timeout
• let a=[];for(;;)a.push(new Array(1e5).fill(0)) → stopped by the memory limit
• [3,1,2].sort().join() → normal compute returns 1,2,3

Or run a raw WASM module — the same sandbox one level lower: a wasm binary with only the memory + output capabilities the host grants it. A module that imports anything else can't even instantiate.

What makes this a real sandbox (all verified, not decorative):
• No host access — the module only sees emitInt / emitByte + its own capped memory. A module that imports anything else (a network call, a file read) fails to instantiate — it can't acquire a capability the host never handed it.
• Time-bounded — an infinite loop can't be interrupted from inside plain WASM, so the module runs in a worker thread the host terminates when the timeout hits. Try the "Infinite loop" example.
• Memory-bounded — the memory has a hard maximum, so a module that grows memory forever is stopped by the cap. Try the "Memory bomb" example.
To run arbitrary JavaScript or Python this way, you'd drop a language interpreter compiled to WASM (e.g. QuickJS) into this same harness — the isolation model is identical.
