What parallax occlusion mapping cannot represent
POM displaces along a heightfield — h(u,v), one height per texel. A function cannot return two values, so an overhang, a hole you can see through and an undercut are not hard for this technique, they are unrepresentable. The silhouette never moves either: however deep the interior looks, the quad's outline stays a quad.
The loss is not "detail looks worse". On the fixture above the heightfield keeps every solid cell and fills in the empty space underneath the overhang — which is exactly why POM is convincing and wrong: you never see geometry go missing, you see solid where there should be a gap.
SweK already renders the other side of this line: a voxel DDA marches a volume, and a volume has no one-height-per-texel restriction — see ray-march-demo. The browser has no tessellation stage (neither WebGL2 nor WebGPU exposes one), so the usual answer to this limitation is not available here; marching the volume is.
