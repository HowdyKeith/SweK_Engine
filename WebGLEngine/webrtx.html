Ray tracing in the page

Vulkan's ray tracing pipeline — raygen, closest-hit, miss, a shader binding table, a BVH — as pure WebGPU compute. No hardware RT cores, no special browser build. It is also unmaintained since 2023 and not shipped with this tree. All three are the point.

What this is, and what it is not

1 — Can this address even do it

Asked first, because it outranks the hardware. navigator.gpu is secure-context only, so on SweK's own LAN address there is no WebGPU at all — and a page that reported “no adapter” there would be blaming the machine for what the URL did.

2 — Build it yourself

There is nothing to download. Upstream publishes no build at all, so unlike this tree's other opt-in page there is no digest to pin — every consumer compiles their own and two builds differ. What is pinned instead is the recipe, and every line of it was measured by running it. The result is verified by behaviour in step 3.

    Then stage dist/ at /vendor/webrtx/, or pick index.js with the file button below.

    3 — The smoke test (behaviour, since there is no digest)

    Four things, in order, each a real call: does it patch requestDevice; does asking for the ray_tracing feature install the pipeline API; does beginRayTracingPass appear on a command encoder; and does a bottom-level acceleration structure actually build from real triangle vertices — which is the one that proves the BVH WebAssembly executed rather than merely loaded.
