gputaskman

a monitor for what is inside your GPU, and a one-button session that starts a model and saves the numbers — a separate project (shanselman/gputaskman, MIT), linked here for convenience. It does not touch any SweK protocol.
Early, experimental software that this engine did not write. The install button below runs uv tool install gputaskman or pipx install gputaskman on this machine, which fetches a package from PyPI; the engine does not pin or scan it. It reads NVIDIA and AMD GPUs (Windows 10/11 and Linux; Apple Silicon from a clone); Intel GPUs are not supported yet. The engine's bridge must be running on this machine. The Run the GPU brain and watch it button in section 4 also starts the engine's own swarm tool (node tools/ship/gpuSwarm.mjs --hardware), which launches a browser and keeps the card busy for a minute or two.

How to use this, step by step

  1. Start the engine's bridge as you usually do (it listens on port 8787) and keep this page open at http://localhost:8787/gputaskman.html.
  2. Press Check this machine (section 1): it lists uv, pipx, Python, gputaskman and Ollama.
  3. Press Install with uv (or pipx) in section 2. If it still says gputaskman is not installed afterwards, close the bridge and start it again from a NEW terminal (uv and pipx add ~/.local/bin to the PATH for new terminals only), then press Check again.
  4. Get a model into Ollama, in a command prompt: ollama pull qwen2.5-coder:7b (about 4.7 GB; it fits an 8 GB card). ollama list shows the exact names. Ollama has to be running: the Windows app starts it, otherwise run ollama serve.
  5. In section 3 type the model name and press Start the model, run gputaskman, save a snapshot. A large model can take minutes to load; the progress box shows each step.
  6. When it ends, the JSON is in section 5 and is saved in brain/rig-results/gpu-snapshots/. Read it, then send that file (or paste the box).
  7. Optional, section 4: Sample now watches the card for the seconds you set while you run something yourself (a game, the pilot-swarm demo, a model in another window), and Run the GPU brain and watch it runs the engine's swarm of pilots on the card with snapshots before, during and after. Each gputaskman snapshot takes a second or more, so the gap between snapshots is at least that. For a long model answer, put a number of seconds in the “also sample while it answers” box in section 3.
What the numbers mean. “On the GPU” is Ollama's own count of how much of the model sits in video memory; the rest is in system memory, which is slower. Tokens per second is the speed of the short test answer. The “busy” snapshot is taken about 2.5 seconds into that answer.
Known limits. It has been run against the real gputaskman 0.3.3 only on a machine with no GPU (its snapshots were empty), and never against a real Ollama or a graphics card. The README of gputaskman does not describe its JSON; the engine reads the fields of version 0.3.3 from the program's source (the device readings, and each program's name, runtimes, GPU share and memory) and stores every snapshot exactly as it prints it. Windows is untested. The session does not start Ollama and does not download models, and a model that thinks before it answers spends part of the test's tokens thinking.

4. Watch the GPU over time



  
gputaskman and nvidia-smi are asked together, again and again, and every answer goes into one file with the time it was taken (seconds since the start). The summary reads which programs used the card, under which runtime (Direct3D, Vulkan, CUDA), and what the card's utilization and memory did. At most 120 snapshots; the file keeps the full text of the first few megabytes and marks the rest left out.

  
A. 

  
A watches the card while you run something yourself: start it, then start the thing, and let it run.

  
B. 

  
B runs the engine's swarm of pilots (node tools/ship/gpuSwarm.mjs --hardware: the CPU twin, then one GPU dispatch a tick) with two snapshots before, one every wait while it runs, and two after. It does NOT write the swarm's results file: the timings it prints were taken while being watched, and are in the JSON only. If the browser falls back to a software adapter the page says so and the card was not used.
