Install FSR caches — opt-in

The frame-generation measurement data the release zip leaves out. Nothing downloads until you press Install.

What these are

fsr.html's frame generator was put through a run of pre-registered hypotheses (H1–H16): does a gate, a rule or a learned model know when generating a middle frame beats cross-fading? Each one was answered on per-block feature rows harvested off the page itself by a WebGPU browser drive (tools/ship/genGateTrain.mjs) — minutes per scene, up to an hour per harvest. Those harvests are these files. The measurement gates (tools/ship/frame*Measure-selfcheck.mjs, genGate*Measure-selfcheck.mjs and their siblings) re-derive every verdict from them.

Nothing at runtime reads them — no page, no bridge route, no engine module. Without them every one of those gates prints a named SKIP that says it is not a pass, and the engine itself is unaffected. Install them if you want to re-check the FSR arc's claims on this machine.

What this page will not do

  • Fetch a file the manifest does not name. The bridge refuses any other name and never writes outside WebGLEngine/fsr-caches/.
  • Keep a file whose hash is wrong. A truncated, corrupted or substituted download is deleted, not kept with a warning.
  • Re-harvest. Regenerating these needs a WebGPU browser driving fsr.html; that is the runners' job (node tools/ship/frameGate.mjs and its siblings), followed by node tools/ship/fsrCaches.mjs --write-manifest.
