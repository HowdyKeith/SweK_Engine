  1. Get the engine. download the current build, then unzip it and open the WebGLEngine folder inside. You need Node.js installed — nothing else.
  2. Check in. From inside WebGLEngine, run this once. The lighthouse URL is already in the line, and it is remembered afterwards: 
    …

    It computes this machine's fingerprint — the same 50-subsystem computation the hub would have run if it could reach you — and pushes it here. After the first run, plain node tools/roundhouse/lighthouse_checkin.mjs works with no arguments.

  3. That's it. You will appear on the hub's roster with your platform, your master hash, and how long ago you checked in. If your hash differs from everyone else's, that is the interesting result, not a failure — it is the whole reason a fleet exists.

    To keep checking in, add that command to a scheduled task or cron. It exits non-zero if the lighthouse was unreachable, so a retry loop needs nothing else.

Why push and not pull? The hub normally fetches each peer's fingerprint directly, which works on a local network. Your machine is almost certainly behind NAT, so the hub has no address it can dial — the connection has to start from your side. That is what this address is for.
