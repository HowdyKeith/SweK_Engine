Android in the browser — opt-in

A front door to somebody else's project. Nothing of theirs is in this engine.

Whose work this is

This engine did not write an Android screen-mirroring stack. This page installs and runs one that Sergey Volkov (Netris, JSC) wrote, on your machine, as its own process.

⚠ This one binds to every interface, and has no login

Read out of their own source, not assumed:

  • server.listen(port, cb) in src/server/services/HttpServer.ts — no host argument anywhere, and Config.ts's ServerItem type has no host field to set one through.
  • SCRCPY_LISTENS_ON_ALL_INTERFACES: true in their default build config, used here unmodified.
  • No authentication of any kind — upstream's own README says so.

Together that means: while this is running, anything on your network that can reach the port can see and control any Android device this server can reach over adb. There is no password to stop it.

The neighbouring RDP page solves its version of this by starting upstream's proxy with their own -listen 127.0.0.1 flag — their code unmodified, just a different argument. ws-scrcpy has no such flag, so there is nothing honest to pass. Adding one would mean editing their TypeScript and running a fork of their behaviour, which this page refuses to do. So the exposure is stated instead of hidden, and warned on every time you start it.

1 · Install & build

Clones the pinned commit into … (outside this tree) and runs their own five-stage build: git clone → checkout → npm install → npm run dist (webpack) → npm install inside dist/. Measured on a clean machine: about 65 seconds total, ~770 packages. Needs a C/C++ toolchain (node-pty is a native module built by node-gyp). No JDK needed — upstream ships the Genymobile scrcpy-server.jar already built, unmodified.
