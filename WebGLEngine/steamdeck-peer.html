🎮 SweK Steam Deck Peer — SteamOS / Linux desktop

A Steam Deck is an x86_64 Linux computer. It does not run a subset of the engine the way a phone does — it runs the engine. This page says what that buys, and is equally plain about the part nobody has ever verified on real hardware.

where it sits against the other two peers

peerwhat it actually runs
🍏 iOSthe portable physics subset in the page, plus a GPU audition. No Node, no daemon — a guest in Safari
🤖 Androida subset under Termux with partial Node, a real ballot and a GPU audition — a guest in a sandbox
🎮 Steam Deckai-bridge/server.js itself — the same file the desktop runs. A peer in the ordinary sense, not a guest
The jump from Android to Deck is not a matter of degree. The first two are as capable as their host lets them be; the third has no host in the way — it is the host.

Bottom line: a Deck is a full compute-and-fleet peer — the only one of the three that runs the engine rather than a subset of it. Its GPU story is the unproven half, and the CPU fallback means an unproven GPU costs capability, never a working brain.
⚠ What has never been verified, stated once and plainly.
No physical Steam Deck has ever run any of this. Every row above marked MEASURED was measured on generic x86_64 Linux — which is architecturally what a Deck is, and is why those rows are worth something. Every row marked NOT VERIFIED depends on something this box does not have: an AMD RDNA2 GPU, SteamOS's read-only root, Distrobox, or Game Mode. Those are reasoned from Valve's own documentation and from the hardware, and reasoning is not measurement.

tools/ship/steamdeckLaunch-selfcheck.mjs makes the same disclosure at the bottom of its own run, so the gate and this page cannot drift apart on it. The first real Deck to run ./install-steamdeck.sh settles the unproven rows — and until one does, they stay marked.

how to make this Deck a peer

Switch to Desktop Mode first — these are shell scripts and want a terminal. Then, from the engine folder:
./install-steamdeck.sh     # OS + Node check, deps, chmod. Offers adb (optional) and Distrobox guidance
./start-steamdeck.sh       # runs the bridge in the foreground; Ctrl-C stops it
The installer never installs anything behind your back: when Node.js is missing it prints the Distrobox route and stops, rather than running pacman itself — a package installed into a read-only root would disappear on the next SteamOS update, silently. The launcher opens no browser of its own, because server.js already calls xdg-open on Linux; two openers racing was a real bug once. The GPU brain starts alongside the bridge and falls back to CPU on its own.

once it is running

Nothing special to register — that is the point of the ladder above. The Deck answers the same routes every peer does, so it shows up wherever peers show up: the fleet console, the /lighthouse roster, the version-check sources on this page's header. Open /lighthouse from any box on the LAN and it should be listed by name.

If it is reachable by IP but not by .local, that is the mDNS row above — and as of v4147 that guard no longer fires on Linux at all, so a Deck on a recent build should advertise itself normally.
