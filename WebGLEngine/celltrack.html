🧬 Cell Tracking

Following individual living cells through time — and a place for a curious scientist to join in.

What this is

A microscope films a zebrafish embryo as it grows: a 3D movie where thousands of cells drift, divide, and rearrange, frame after frame. This project tracks every cell through that movie — detecting each one, following it from frame to frame, and spotting the moment it divides into two — so you end up with a family tree of the embryo: which cell became which, all the way down.

It's a working entry for the royerlab Kaggle cell-tracking competition, built and validated end-to-end. The same idea drives real developmental biology and cancer research: to understand how a body builds itself, you have to be able to follow the cells.

How it works, in four steps

  
    
    
  1. Detect — find every cell nucleus in each 3D frame (a blob detector tuned to the cells' size).
    2. 
    
  2. Link — decide which detection in the next frame is the same cell as this one.
    3. 
    
  3. Divisions — where one cell becomes two, record the split so the family tree branches.
    4. 
    
  4. Score — compare the tracks to a known answer and write a submission in the competition's format.
    5. 
  

  
Two ways to do the linking: a fast frame-by-frame baseline (Hungarian assignment), and a
     smarter whole-movie optimizer that decides every keep/link/appear/divide at once (using royerlab's own
     tracksdata, solved by the free SCIP solver). On clean data the simple one is perfect; on realistic
     noisy data the optimizer wins:

For a teacher & students

  
You don't need real microscope data or a lab to start — the pipeline ships a synthetic embryo
     generator that makes movies matching the real format, so a class can run the whole thing today:

  
    
    
  1. Generate a synthetic embryo movie (you control cell count, division rate, noise).
    2. 
    
  2. Track it with either linker and watch the lineage tree build in the viewer.
    3. 
    
  3. Break it on purpose — add noise, drop detections — and see the score drop, then tune it back.
    4. 
  

  

    Classroom angles. Cell division & lineage as a family tree; how scientists turn a fuzzy image into
    data; what "an algorithm makes mistakes and we measure them" really means; an honest look at accuracy,
    trade-offs, and why the fancier method isn't always better. It connects biology, data, and a little bit of
    optimization — without any black boxes.
  






  
Contribute as an external peer

  
SweK Engine runs as a small fleet of peers — machines that share work over the network. A science
     teacher next door can join as an external peer: no install ceremony, just a link the operator shares.
     What that lets you do:

  
    
    
  • Explore the tracked datasets in the viewer, from your own laptop.
    • 
    
  • Run a tracking job on your machine — generate synthetic data, track it, evaluate the score —
        and have the results show up for everyone on the fleet.
    • 
    
  • Bring data or ideas — a real dataset, a tuning idea for sigma/threshold,
        or a classroom experiment worth sharing.
    • 
  

  
Getting connected: the operator opens an access link for you (the engine can share a secure tunnel URL
     to a trusted peer), you open it in a browser, and you're in — same pages, same viewer, same pipeline. The
     controls for the pipeline itself live in server.html
     under the cell-tracking tools.

The honest state of it

  
This is a classical-CV baseline, not a trained neural network — it gets you a real,
     scoreable result today, and it's tuned and validated on synthetic data built to match the real format and
     physical scale. On actual microscopy you'd re-tune the detector for that scope's noise and cell density. It's a
     genuine, honest starting point — which is exactly what makes it a good thing to learn on and build from.
