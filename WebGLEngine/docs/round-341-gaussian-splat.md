# Round 341 — Gaussian Splats in the engine + install panel additions

You asked: "Can we do splat?" Yes. Three-tier plan, this round is Tier 1.

## Tier 1 (this round): WebGL splat renderer in the engine

Two new modules in `engine/`:

### `splatParser.js`

Parses both common splat formats:

- **`.ply`** — INRIA / Hunyuan3D / CRM / LGM standard. ASCII header + binary little-endian body. 14 required float32 properties per Gaussian (pos, scale, rotation quat, SH band-0 color, opacity). Higher SH coefficients (view-dependent lighting) are parsed away because they 10× the file size and aren't needed to "see the asset."
- **`.splat`** — the compact 32-byte format some converters emit. Position + scale as float32, color/quat as uint8 with dequantization.

Dispatcher picks by file extension, or sniffs the magic bytes if the URL doesn't include one. Returns a clean struct: `{ count, positions, scales, quats, colors, opacities, bbox }`. Bbox is auto-computed for sane default placement.

### `SplatRenderer.js`

WebGL2 instanced billboard rendering:

- Each Gaussian is a screen-aligned quad sized from the geometric mean of its per-axis scale (which is stored in log-space).
- Vertex shader pulls per-instance position/scale/color/opacity from divisor=1 attributes; pushes quad corners outward in view space.
- Fragment shader applies **`exp(-r² · 4)`** Gaussian falloff, multiplied by sigmoid-opacity. Discards at r² > 1 (outside the implicit disc) and at α < 0.003 (negligible) to save bandwidth.
- **CPU sort each frame**: only re-sorts if the camera actually moved. Built-in `Array.sort` on indices by descending camera distance. For massive splats (>200k Gaussians) this'd need a radix sort — that's a Tier-2 optimization if you hit it.
- **Transparent pass**: `glBlendFunc(ONE, ONE_MINUS_SRC_ALPHA)`, `depthMask(false)` so splats don't pollute the depth buffer.

Slotted into the main loop right after `particles.render()` and before `bloomPass.apply()` so splats:
1. Composite over opaque geometry correctly
2. Contribute alpha to the bright pass for bloom

### Console API

```js
splat.load("http://127.0.0.1:8188/view?filename=scene.ply")  // returns SplatRenderer
splat.load(url, { position: [0, 5, -10], scale: 2.0 })
splat.list()
splat.clear()
splat.remove(sr)
```

Drop a splat from anywhere reachable by HTTP — your ComfyUI output, a HuggingFace URL, a local file via `?filename=...`. Default position is ~10 units in front of the camera. Console logs the Gaussian count + bbox on load so you immediately know if the file parsed.

## Tier 2 (later): true Gaussian rendering

What's missing from Tier 1:
- **Anisotropic covariance projection** — true Gaussian splats are ellipsoids (each splat has 3 independent scales + a rotation quaternion). Tier 1 uses isotropic discs from the max scale. This means a splat that's "long and thin" renders as a fuzzy circle instead of an oriented ellipse. Looks like a soft point cloud, not a true splat.
- **Spherical harmonics for view-dependent color** — splats with sharp reflections lose specular detail.

Real-world impact: assets generated by Flowty-CRM or Hunyuan3D will look "fuzzy but obviously 3D," not photoreal. For a portfolio piece showing "yes the engine supports splats," that's enough. For "wow look at this rendering quality" we need Tier 2.

## Tier 3 (much later, optional): VBA side

Same pipeline in the VBA OpenGL engine. The CPU sort is straightforward; the shader is a port of the WebGL one. The big lift is fitting alpha-sorted dynamic VBOs into the existing pipeline. Skip unless you decide it's a portfolio bullet point.
