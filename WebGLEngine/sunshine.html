☀️ SweK Sunshine Host

The host half. LizardByte/Sunshine (GPL-3.0) streams this machine's screen; Moonlight V+ (GPL-3.0) on a phone dials in. Video and audio go down, input comes back up — touch, stylus, gyroscope and gamepad, at up to 165 Hz.

⚠️ No Sunshine has ever run against this bridge.
The box it was written on has no GPU, no Sunshine binary and no flatpak. Detection and every refusal are gated and run; the install, start and stop commands are transcribed from LizardByte's own documentation and have not been executed. Rows below say which is which, one by one, rather than hiding it in a footnote.

Why this is a host button and not a Moonlight plugin

Keith asked whether non-streaming features could be pushed into Moonlight V+. Read for real, that app has no ServerSocket, no HttpServer, no exported service and no content provider — four exported components in its whole manifest, of which one is the main activity, one a home-screen widget and one the shortcut trampoline used below. Its top-level LuaScripts/ folder looks like a plugin surface and is not: they are Wireshark protocol dissectors inherited from upstream Moonlight, for debugging the NVIDIA stream. So there is nothing to push into. Moonlight is a client; you add features to the host, and the client relays them.

Pairing happens in Sunshine's own web UI (https://localhost:47990, self-signed — the browser warning is expected). The phone shows a four-digit PIN and a human types it there. This bridge will not do that for you; see the refusals below.

2 · Launch Moonlight on a phone, from here

The one push surface that client has: ShortcutTrampoline is exported="true" and reads its host from an intent extra. Launch-only and one-way — no reply, no status, no second command. Needs adb (the Steam Deck installer offers android-tools since v4142).

—

The UUID may be left empty: the trampoline falls back to looking the host up by name, so the Deck never has to learn the phone's internal id for a machine.
