The boundary is not where accuracy dies

Three consecutive rounds excluded "boundary cells" by name. Taken as a subject, the first measurement says the exclusion was mostly unnecessary: of 94 boundary cells, 92 reproduce a linear field exactly. Two non-collinear differences determine a two-vector exactly — a boundary cell with two neighbours is not a degraded interior cell, it is a fully determined one.
The real defect is smaller, sharper, and of a different kind. A gradient in 2D has two unknowns and each neighbour supplies one equation, so a cell with a single neighbour cannot determine it — not inaccurately, not at all. That is a rank statement, and no amount of refinement touches it.

1. The census

The underdetermined set is exactly two, at every mesh size, while boundary cells go 30 → 62 → 126 → 254. Refinement never fixes it and never worsens it — the signature of a rank defect rather than a discretisation error. They are the corners where a triangle owns two boundary edges; this triangulation cuts every square the same way, so only two of the four rectangle corners produce one.

2. What those two cells actually know

The full gradient reads exactly 100% wrong, because the code wrote zero. That is not an accuracy figure — gx = gy = 0 against a unit-normalised truth is exactly one. An error of exactly 1.000 is a refusal, not a measurement. But the component along the single available lever is exact: half the gradient is recoverable perfectly and half is unknowable from cell averages alone. The honest answer is a partial gradient plus a named unknown, and rank, along and the direction now carry it instead of a zero that says nothing.
And this arc has produced three different sets all called "the boundary", no two equal. A boundary face means a missing equation; a boundary node means an invented value; rank-deficient means the system cannot be solved. Which one you mean decides the answer — the previous round read 32% or 1.6e-14 for the same scheme on the same mesh depending only on that choice.
