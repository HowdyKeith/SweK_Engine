🍏 SweK iOS Peer — iPhone / iPad

iOS is a different animal from Android. There is no Termux, no unrestricted Node, and no way to push an app to a phone. This page is honest about what an Apple device can and cannot do as a peer, and it runs the parts that DO work, right here.

Feature flags affect Safari only, not WebKit generally — WKWebView gets a feature when it is enabled by default for the OS, which for WebGPU means iOS 26. On iOS 18 a wrapper is worse than Safari: it would kill the GPU audition above. On Android the same wrapper is a win (no secure-origin rule on the LAN); here it is a downgrade

Bottom line: an iOS device is a GPU-audition and console peer, plus a real (if partial) physics peer via the in-page subset. The compute-daemon half that makes the Android peer a background worker has no home on iOS — that is a property of the platform, not a gap we can code around.

wake this device from the hub

v3332. The hub publishes one short line to an ntfy topic; iOS wakes ntfy's app and shows it. This does not make the page a background worker — the notification arrives in ntfy's app, you tap it, and that opens this page. It converts “the phone is unreachable” into “the phone can be summoned”, which is a smaller and more honest claim.

Configure it on the hub, not here: write ~/.voxelbridge/ntfy.json or set the SWEK_NTFY_* variables. A public ntfy host with no auth token is refused — a topic name is not a secret, and anyone who knows it can read and publish.

the address matters more than the device

Open this over the https tunnel, not the LAN IP. navigator.gpu is secure-context only, and so are crypto.subtle, VideoEncoder, getUserMedia and navigator.storage.estimate. SweK's primary origin is http://<lan-ip>:8787, which is neither https nor localhost. Measured in Chromium, one server, two origins: from 127.0.0.1 every one of those exists; from a LAN IP every one is undefined. So the GPU audition below is not gated on the phone at all — it is gated on the URL you opened, and a device that looks incapable on the LAN is fine through the tunnel. Same rule ui/codecProbe.mjs recorded for WebCodecs at v3735.

run the portable physics subset — right here, on this device

This runs the arithmetic-only, answer-key-bearing checks (Basel π, even-zeta closed forms, the strict-trig identity, the Schwarzschild radius and ISCO) directly in Safari's JS engine. If they pass here, the strict core is bit-faithful on Apple's JavaScriptCore.

audition this device's GPU — the magmap kernel

The same unchanged magmap WGSL the Android round runs, on the Apple GPU. Needs iOS/iPadOS 18+ (Safari 18) for WebGPU. The result grades the Apple GPU as its own vendor family against a tolerance set before any Apple GPU met this kernel.
(the same page the Android peer uses; it detects the adapter and names Apple first-class)

optional: the native-ish path via a-Shell

a-Shell is a free, notarized App Store terminal that runs a real sandboxed shell (no jailbreak). It has no Node, but it does have a JavaScript engine, so it can run the same portable subset off the browser. Slower and manual, but it is a genuine on-device shell.
# in a-Shell, after downloading the peer files (Files app, or curl from your engine):
curl -fsSL "ORIGIN/tools/roundhouse/portableSuite.mjs" -o portableSuite.mjs
# a-Shell's `jsc` (JavaScriptCore) runs ES modules:
jsc -m portableSuite.mjs
If jsc is not present in your a-Shell build, the in-page runner above is the reliable path — it uses the same module.

move files - copyparty on the phone

This page could run the physics subset and not move a single file. copyparty is a one-file Python server that runs in a-Shell and speaks http, WebDAV and FTP, with resumable uploads and downloads.

SweK does not start it and does not install it for you. It is registered in Auto-Install (v3166) with autoRun deliberately OFF: a file server that starts itself is a decision about what is exposed and to whom, and that is yours to make, not a registry's.

The port is 3923 by default - copyparty's own, and it collides with nothing SweK claims (8787 the engine, 8080 spaceprojectsim). There is no auto-allocator, and that is deliberate: the tree's freePort() is a KILL - it frees a port by terminating whatever holds it - so a collision here is REPORTED for you to resolve, never resolved by force. A port that silently drifted would hand you a URL that changes between sessions.

Read this before serving read-write. copyparty with no accounts gives everyone on the network read/write access to the folder it serves - its own README says so. The command the checker prints for iOS is -v .::r, read-only, which is the safer default for a phone. It also carries real CVEs and publishes advisories, so a copy left running is a thing to keep updated rather than forget.
